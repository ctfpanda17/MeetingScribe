# 會議記錄助手 MeetingScribe

開會當下即時把每個人說的話轉成文字，並依「聲音」自動分出不同的說話者。全部在本機執行，音訊不會上傳到任何地方。

- 語音辨識：可自行選擇 / 加入模型（預設 SenseVoice；也支援 Whisper、Breeze-ASR-25、NVIDIA nemotron、Paraformer 等）
- 說話者分辨：pyannote 換人偵測 + ECAPA / TitaNet 聲紋 + 串流式說話者分離（自動判斷人數）；搭配 Chrome / Edge 擴充功能時，直接使用 Meet / Teams 顯示的與會者姓名
- 中文輸出自動轉繁體（OpenCC），並修正全形標點

## 給使用者：怎麼用

1. 解壓縮 `MeetingScribe.zip`，執行資料夾裡的 **`MeetingScribe.exe`**
2. 第一次開啟會自動下載預設模型（約 0.5 GB，需要網路，網路中斷會自動續傳），之後可離線使用
3. 選「音源」：
   - **線上會議 Meet / Teams（對方 + 我）**：預設選項，對方的聲音從電腦收，你的聲音從麥克風收
   - **線上會議（只記對方）**：不收你的麥克風
   - **實體會議（麥克風）**：會議室裡大家對著同一支麥克風
   - **匯入錄音檔**：事後整理錄好的檔案
4. 按 **● 開始記錄**，文字會即時出現（灰色斜體 = 還在說，一般字體 = 這句已確定）。右上角 ☾ / ☀ 可切換深色 / 淺色
5. 會議中或會議後都可以：
   - 右側把「說話者 1」改成真名（按 Enter）
   - 同一個人被分成兩位 → 按名字旁的「⋯」→「合併到…」
   - 某一句標錯人 → 點表格裡的說話者名稱改成別人
   - 字聽錯 → 雙擊內容直接修改，Enter 完成
   - 按「記住」儲存某人的聲紋，下次開會會自動認出他
6. 紀錄會**即時自動存檔**到程式資料夾裡的 `會議紀錄\`（Markdown + JSON）；按匯出（TXT / Markdown / JSON）也會直接存到同一個資料夾

### 更換語音辨識模型

上方「辨識模型」選單可以切換已安裝的模型。要加入新模型有兩種方法：

1. **貼網址自動下載**：按「＋ 新增模型」，貼上 Hugging Face 網址（例如 `https://huggingface.co/MediaTek-Research/Breeze-ASR-25`），按「檢查」會顯示模型類型和大小，再按「下載並加入」。只會下載辨識需要的檔案；下載時可以關掉視窗，會在背景繼續。
2. **自己放資料夾**：把整個模型資料夾複製到 `models\asr\` 底下（資料夾名稱隨意），再按辨識模型旁的「⋯ → 重新整理模型清單」。

支援的格式：

| 類型 | 需要的檔案 | 例子 | 硬體 |
|---|---|---|---|
| Whisper 系列（含微調版） | config.json + model.safetensors + tokenizer | Breeze-ASR-25、whisper-large-v3-turbo | 建議 NVIDIA 顯示卡 |
| NVIDIA nemotron 串流 | config.json + model.safetensors | nemotron-3.5-asr-streaming-0.6b | 建議 NVIDIA 顯示卡 |
| sherpa-onnx | tokens.txt + .onnx | SenseVoice、Paraformer 串流、Zipformer | CPU 即可 |

我們用同一段中文會議錄音比較的結果（3 位說話者、5 句話，全部模型都正確分出說話者）：

| 模型 | 錯字 | 一句講完到文字確定 | 硬體 |
|---|---|---|---|
| SenseVoice（預設） | 0 | 約 0.2 秒 | CPU |
| Breeze-ASR-25 | 0 | 約 1.1 秒 | GPU |
| Nemotron 3.5 串流 | 2（行銷→行消、時程→時辰） | 約 0.3 秒 | GPU |
| Paraformer 串流 | 4，且沒有標點 | 幾乎即時 | CPU |

### 在 Google Meet / Microsoft Teams 使用

Meet（瀏覽器）、Teams（桌面版或網頁版）、Zoom、LINE 都可以用，程式收的是「電腦播出來的聲音」，不需要安裝任何外掛，也不用把機器人加進會議。

1. 先加入 Meet / Teams 會議
2. 開啟會議記錄助手，音源選「線上會議 Meet / Teams（對方 + 我）」
3. **會議聲音**：選你聽會議的裝置。戴耳機就選耳機，用喇叭就選喇叭（★ 是系統預設）
4. **麥克風**：選你在 Meet / Teams 裡用的同一支麥克風（你自己說的話會自動標成你）
5. 用喇叭外放時請勾「外放喇叭防回音」；戴耳機可以取消勾選
6. 按「開始記錄」

#### 讓逐字稿直接標上與會者姓名（Chrome / Edge 擴充功能）

在瀏覽器開 Google Meet 或 Teams 網頁版時，可以加裝「會議記錄助手 連接器」。它會把會議軟體顯示的「誰正在說話」傳給本機程式，每位遠端與會者都會直接標上他在會議裡的名字，也會用來修正說話者。

- 安裝：Chrome 開 `chrome://extensions`、Edge 開 `edge://extensions` → 打開「開發人員模式」→「載入未封裝項目 / 載入解壓縮」→ 選程式資料夾裡的 `extension`（詳見資料夾內的「安裝說明.txt」）
- 連上後，程式上方會出現「🔗 Meet 已連接」或「🔗 Teams 已連接」
- 資料只傳到這台電腦（127.0.0.1），只有擴充功能能傳，一般網頁不行
- 會議室裡多人共用一支麥克風時，會議軟體只看得到一個人，這時仍由聲音分離區分（例如「會議室 (1)」「會議室 (2)」）
- 誰說了算：遠端與會者以**會議軟體顯示的發言者**為準（直接標上他在會議裡的名字）；你自己以**麥克風**為準；只有共用麥克風的會議室或沒裝擴充功能時，才靠聲音分離
- 目前已在 **Teams 網頁版**實測過（2026-10，用虛擬音訊線播放對話）：說話標示比實際講話晚約 0.2 秒出現、0.7 秒消失，程式已自動補償；逐字稿每句都正確標上了與會者名字。**Google Meet 尚未實測**，畫面結構若不同可能需要調整
- 擴充功能沒反應時：到 `chrome://extensions`（或 `edge://extensions`）→「詳細資料」→「網站存取權」設為「在所有網站上」或至少允許 `teams.microsoft.com` / `meet.google.com`，再重新整理會議分頁


> 小提醒：錄音或記錄會議內容前，請先告知與會者並取得同意。

### 電腦需求

- Windows 10 / 11（64 位元）
- 預設模型（SenseVoice）用 CPU 就能即時辨識；Whisper / Breeze / nemotron 類模型建議有 NVIDIA 顯示卡（6 GB 以上 VRAM）
- 硬碟空間：程式約 3.3 GB，模型另計（0.25～3 GB 不等）

### 檔案放在哪裡

所有東西都在程式自己的資料夾裡，不會寫到電腦其他地方（整個資料夾可以直接搬移或刪除）：

```
MeetingScribe\
  MeetingScribe.exe
  extension\   ← Chrome / Edge 擴充功能
  會議紀錄\    ← 會議逐字稿（自動存檔 + 匯出）
  models\asr\  ← 語音辨識模型（每個模型一個資料夾，可自行增減）
  models\      ← 另有聲紋模型
  data\        ← 設定、記住的聲紋、記錄檔 app.log
```

請把資料夾放在有寫入權限的地方（例如桌面、下載、D 槽），不要放在 C:\Program Files。

### 怎麼分辨是誰在說話

程式不是一句一句單獨比對聲紋（短句的聲紋太不可靠），而是用「串流式說話者分離」：

1. **換人偵測**（pyannote segmentation 3.0）：每 0.5 秒分析最近 8 秒，在同一段裡並排比較聲音，標出每約 17 毫秒是哪個聲音在說話，包括插話、重疊、只說「嗯」「對」的短回應。
2. **即時對應到人**：每個聲音用它在這 8 秒裡的全部發言算聲紋（ECAPA），對應到會議中的說話者；同一段裡被分成不同聲音的不能是同一人。每一刻由多個分析段投票決定。
3. **整場重新分群**：背景每 15 秒用整場會議的所有聲音片段重新分群（TitaNet 聲紋 + 自動調整的頻譜分群），自動判斷有幾個人、把同一人被拆成兩位的情況合併，並回頭改正之前的句子。

用真實節目測試（以兩個獨立參考模型都同意的部分為準）：

| 樣本 | 實際人數 | 說話者正確的時間比例（開會當下的畫面） |
|---|---|---|
| Podcast（兩位男聲、快速來回） | 2 | 約 99% |
| 訪談節目（3 人、情緒起伏大、常互相插話） | 3 | 約 97% |
| 改版前的做法（逐句比對聲紋） | | 約 51%（且人數錯誤） |

限制：
- 開會途中顯示的說話者是「目前的判斷」，可能偶爾多出一位，背景校正和會議結束時會自動改正。
- 第一次開口只說半秒（例如「好的」）的人，聲音資訊不足，可能被歸給別人。
- 兩人長時間同時說話時，重疊部分的文字仍可能不準。

### 背景自動校正

即時判斷只能用「到目前為止」聽到的聲音，所以程式會在背景每 6 秒回頭檢查剛講完（最近 90 秒內）的句子，會議結束時再整理整場：

- **藏在句子裡的短插話**：例如別人講話中間有人說了一句「對啊」，會被切出來、標上正確的人。
- **認錯人的句子**：會議剛開始時聲紋樣本少，之後累積更多聲音後，明顯認錯的句子會自動改正。
- 被改正的句子會標「已校正」；太短、聲音不足以判斷是誰的句子（例如只說「好的」）會先歸給前一位說話者，並標「待確認」，點名字就能改。
- 你手動改過的說話者或文字，程式不會再動。
- 會議錄音會同時存成 `會議紀錄\<時間>.wav`（約每小時 115 MB，可在右側關閉）。

| 測試情況 | 結果 |
|---|---|
| 有人在別人講話中間說 0.6 秒的「對啊」 | 即時版本會漏掉；背景校正後正確切出、標對人 |
| 第一次開口只說了 0.5 秒的「好的」 | 無法可靠判斷（音色分數幾乎一樣），標「待確認」讓你確認 |

### 已知的電腦相容性問題：華碩 Sonic Studio

實測發現：只要有程式把聲音播放到 **「Sonic Studio Virtual Mixer」** 這個虛擬裝置，電腦上**其他程式**的計算就會被干擾（語音辨識亂碼、顯示卡運算錯誤），推測是該音效驅動的問題。播放到一般喇叭不受影響。
如果你用 Sonic Studio 把「電腦聲音」轉成麥克風，請改用其他虛擬音訊線（例如 VB-Audio Virtual Cable），或更新／移除 Sonic Studio。

### 分辨不準時

- 同一個人被分成兩位：按名字旁的「⋯」→「合併到…」。
- 某一句標錯人：點表格裡的說話者名稱改成正確的人；手動改過的句子程式不會再動。
- 「自動說話者分離」可以在右側關閉，改用簡易模式（依停頓切句、逐句比對聲紋）；簡易模式下會出現「分辨靈敏度」滑桿。

## 給開發者

```
core/       辨識核心（不含介面）
  engines/    語音辨識引擎（nemotron / whisper / sherpa-onnx），依模型檔案自動判斷
  models.py   模型庫：清單、從 Hugging Face 下載（只抓需要的檔案、自動續傳）
  diarize.py  VAD、聲紋、說話者分群
  turns.py    換人偵測（pyannote segmentation）
  streamdiar.py 串流式說話者分離（誰在什麼時候說話）
  cluster.py  整場重新分群（NME-SC 頻譜分群 + 合併）
  session.py  一場會議：音訊 → 分句 → 文字 + 說話者 → 自動存檔
  audio.py    麥克風 / 系統聲音（WASAPI loopback）收音與混音
  paths.py    存檔位置（全部放在程式資料夾）
app/
  main.py     桌面介面（PySide6）
  theme.py    淺色 / 深色主題
  widgets.py  頭像、對話式逐字稿卡片
  model_dialog.py  新增模型視窗
tests/        測試腳本與測試音檔
```

從原始碼執行：

```bash
python -m venv .venv
.venv\Scripts\pip install torch --index-url https://download.pytorch.org/whl/cu130
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python app\main.py
```

打包成 exe：執行 `build.bat`，產出在 `dist\MeetingScribe\`，把整個資料夾壓縮成 zip 即可分享。
